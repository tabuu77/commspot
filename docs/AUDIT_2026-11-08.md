# Code and security audit, v0.5.0 branch (2026-11-08)

Scope: the whole repo on branch `polish-installer` (PR #10): server, client, protocol, updater, installer, CI/release workflows, deploy files. The live VPS (ports, firewall, nginx, Cloudflare) is checked separately from the owner's PC.

## Fixed in this PR

| # | Severity | Finding | Fix | Test |
|---|---|---|---|---|
| 1 | Medium | Anyone could open a hub connection **without the access key** and still receive room events (who joins and leaves, names, mute and share state), because events went to every connection. | Joined members are put in a `room` group; events go only to that group. | `ConnectionWithoutKey_HearsNoRoomEvents` (fails without the fix) |
| 2 | Medium | Screen share viewer decoded a JPEG **before** checking its size. A member could send a tiny file whose header claims 60000x60000 and make every viewer allocate gigabytes and crash. | The size is read from the JPEG header first (`JpegInfo`); anything over 4096 px is dropped without decoding. | `JpegInfo_ReadsSizeFromHeader_AndRejectsGarbage` |
| 3 | Low-Medium | A malformed Opus packet from another member could throw `OpusException` and stop voice for the receiver (receive loop ends). | Decode errors (`OpusException`, `InvalidOperationException`) are caught; the packet is dropped. | Build + existing voice tests |
| 4 | Low-Medium | A UDP send error to one member could stop the voice relay for the whole room. | Send errors are caught per member. | Build + existing relay tests |
| 5 | Low | A bad server address in Settings threw an exception that crashed the app on Join. | Returns "That server address isn't valid." | `BadOrPlainHttpServerAddress_IsRefusedWithoutCrashing` |
| 6 | Low | The failed-join table kept every IP forever (slow memory growth from many IPs). | Expired entries are swept once more than 10,000 IPs are tracked. | `JoinLimiter_ForgetsExpiredIps_SoTheTableCantGrowForever` |
| 7 | Low | Two members could join with the same name (impersonation). | Names must be unique in the room (case-insensitive). | `DuplicateName_IsRefused` |

## Checked and OK

- **Voice/screen crypto:** AES-256-GCM, fresh random key per join sent only over TLS, header authenticated, one counter per direction shared by voice and video (no nonce reuse), replay window after authentication, endpoint learned only from authenticated packets, unknown sessions dropped before any crypto, per-session token buckets (60 voice, 1500 video packets/s).
- **Access key:** constant-time compare of SHA-256 digests, 5 failures per IP per 15 min, generic error, never logged, never saved by the client.
- **Hub limits:** 32 KB messages, 1 parallel call per client, 64 KB request bodies, no detailed errors, forwarded headers trusted from loopback only; nginx passes the real client IP from Cloudflare.
- **Updater:** Ed25519 signature checked before parsing, pinned current and next keys, no downgrades, HTTPS and host allowlist on every redirect, size cap, signed size and SHA-256 on the download, archive may contain only the app exe (no path tricks), rollback if the swap fails.
- **Push to talk:** polls only the bound key; all keys only while picking; nothing stored or sent.
- **Screen capture:** nothing captured before Go Live; video forwarded only to members who chose to watch.
- **Server sandbox (systemd):** non-root user, read-only system, no capabilities, syscall filter, memory/CPU caps so Metal Covenant keeps priority.
- **CI:** all actions pinned to commit SHAs, read-only token by default, the signing key is only exposed to the manifest step in the release job.

## Open items (not fixed here)

| Severity | Item | Recommendation |
|---|---|---|
| Low | Installer and exe are not code-signed, so Windows SmartScreen warns on first run. | Buy a code-signing certificate if the app goes public. Updates are still signature-checked. |
| Low | The installer job installs Inno Setup from Chocolatey when the runner doesn't have it. | Acceptable (build tool only, no secrets in that job). The exe inside is the same file that's in the signed zip. |
| Low | nginx has a request rate limit on `/hub` but no cap on open WebSocket connections per IP. | Add `limit_conn` for `/hub` during the live check. |
| Info | Voice is hop-by-hop encrypted, not end-to-end: the server can hear audio. | Documented in Settings > Security. End-to-end would need a key exchange between members (future). |
| Info | Names allow non-English letters, so look-alike names are possible. | Fine for a private room; revisit with accounts. |
